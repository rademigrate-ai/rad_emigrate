## Concrete acceptance recording requirements

1. For every row, capture source SHA and deployed SHA, timestamp, platform, viewport, locale, identity/role and test transport.
2. Exercise happy path + empty/loading/network failure + forbidden IDOR/RLS + retry + persisted reload + deep link/back/forward + accessibility/keyboard for each visible interactive control.
3. For Auth, validate actual authorized recovery message and link under fixed allowlist, session token expiry, OTP cooldown, logout and protected redirect; never use real user credentials in audit documents.
4. For Documents, validate signed private URLs are owner-bound and never logged/cached and cannot be reused by another real synthetic identity.
5. For Research/Feed, validate a finding produces draft **only**, admin approval is explicit, Feed publishing produces one audited item, unauthorized roles fail, and no AI worker publishes.
6. For AI, include real non-production provider request and source citation quality/freshness cases, plus quota five-question edge cases and concurrency.

## Test-to-acceptance conclusion

`flutter analyze` and `515/515` Flutter tests on the isolated #68+main candidate show a locally consistent Flutter codebase. These results do not prove protected live routes work against the current 47-version Production database, and cannot move a production-dependent gate to VERIFIED_PASS. Human UI sign-off is still required.
